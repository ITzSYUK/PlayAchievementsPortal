# Минимальный клиент LocoRoco: ядро сессии и запуск 0.10

## Результат и границы

0.8 прошла на PSP владельца, игра работала хорошо. Tiny user PRX загружен
в partition 2, наблюдаемая разница free 2560 байт восстановилась при unload.
Минимум user free 567040, largest 566784 байта; 121 замер, успешные check/free
scratch, result=0 и log_error=0. Положительный UID UnloadModule — успех,
требование прежней инструкции ожидать строго ноль было излишним.

Начата интеграция настоящего `rc_client` v12.5.0. В online/src/ra_client_session.c
реализованы spectator-сессия, вход по токену и загрузка по **проверенному хешу**,
ограниченная очередь запросов/ответов, доставка callbacks владельцем клиента,
pause/frame gate и завершение после освобождения запросов транспортом.
На компьютере проверено синтетическое достижение; его условие придумано для
теста, не взято из RetroAchievements. Это не зачёт LocoRoco или реальный аккаунт.

На PSP 0.9 PRX успешно загружен, но StartModule и StopModule вернули
`0x80020001`; status остался `0xFFFFFFFF`, ready/idle равны нулю, user-журнал
не создан. Оба PRX совпали с пакетом. Причина найдена в bootstrap:
`PSP_THREAD_ATTR_USER` ошибочно передавался в SceKernelSMOption.attribute.
Проверка [ModuleMgr](https://github.com/uofw/uofw/blob/master/src/kd/modulemgr/loadModuleChecks_inline.h#L64)
отвергает биты вне [THREAD_SM_LEGAL_ATTR](https://github.com/uofw/uofw/blob/master/src/kd/modulemgr/modulemgr_int.h#L11)
до запуска. Это ошибка нашего кода; последующее исправление 0.10 прошло на PSP.

В 0.10 attribute=0 для StartModule/StopModule: режим entry/stop thread выбирает
ModuleMgr по user-типу PRX. PSP_THREAD_ATTR_USER у непосредственного CreateThread
owner-потока сохранён. Опции запуска явно записываются в bootstrap-журнал.

PSP-пакет 0.10 предназначен для запуска того же rc_client в отдельном user-потоке, включает
spectator, выключает hardcore и вызывает только `idle`. В нём нет транспорта,
ввода аккаунта, загрузки набора, чтения игровой памяти или do_frame по таймеру.
На PSP 0.10 прошла: ready=1, idle достиг 5075, stop/unload/free успешны,
итог result=0 cleanup_result=0 log_error=0. Free восстановилась до 864512,
минимум 245760, largest 237056. FPS и ощущения от игры по логам не измерены.
Следующий пакет — [ограниченный HTTPS lookup, 0.11](HTTPS_CLIENT.md).
Онлайн-достижения ещё не готовы.

## Память и жизненный цикл 0.10

Включается новый kernel bootstrap `RAClientBootstrap`; он ждёт LocoRoco и на
метке 10 загружает RAClientUser **только в partition 2**. Проверяет имя,
user attributes, диапазоны непустых сегментов и сумму размеров не более 288 КиБ.
Text обязан лежать в сегменте модуля, entry — быть выровнен и находиться в text.
В отличие от 0.8 вызывает StartModule с entry stack 8 КиБ в разделе 2. User
модуль создаёт owner thread: stack 16 КиБ, priority 0x60, fixed newlib heap
32 КиБ. CRT main/exit не включён, libc init/deinit выполнены явно; pthread
initializer заменён пустой функцией, дополнительные pthread не создаются.
Libc descriptor I/O (read/write/close) отклоняется с ENOSYS: стандартные SDK
адаптеры тянут NetInet даже без сети. Журнал использует только явные PSP I/O,
stdio игры не закрывается. Перед будущими файловыми/сетевыми операциями нужно
подключить предназначенный для них адаптер, не использовать эти libc функции.
Heap 32 КиБ — конфигурация initial runtime, не достаточный бюджет полного набора/TLS.

Временные guards: до load требуется >=823296 байт free и largest >=288 КиБ.
Файл PRX ограничен 320 КиБ, образ — 288 КиБ: предварительный запас учитывает
их возможное одновременное удержание загрузчиком. Это не квота на остальные
временные выделения loader и не гарантия их пика.
После load перед запуском резервируется запас для heap, двух стеков и 4 КиБ
служебной памяти. При наблюдении требуется free >=192 КиБ, largest >=8 КиБ.
Пороги выбраны для ограниченного первого запуска, достаточность бюджета игры
не доказана. Секундные замеры не предотвращают все возможные OOM.
Защита DDR/MMIO, CFW, игровые кадры/код и partition 9 не меняются.

Bootstrap и owner пишут разные журналы. После stop owner уничтожает сессию,
удаляет свой семафор, закрывает журнал и освобождает heap. Только после done
и join разрешены StopModule/UnloadModule и освобождение control block.
На неопределённом/неуспешном cleanup код и память удерживаются до исправления
очистки или выхода из игры. Fatal libc exit завершает только поток, не игру;
done остаётся нулём, выгрузка не объявляется безопасной.

Если StartModule был отвергнут, cleanup всё равно проверяет состояние через
StopModule. Только явный `SCE_KERNEL_ERROR_NOT_STARTED (0x80020134)` разрешает
пропустить module_stop и попробовать UnloadModule. Control освобождается лишь
после успешной выгрузки; любая другая ошибка stop удерживает ресурсы. Исходная
ошибка запуска сохраняется отдельно от результата cleanup. В 0.9 после отказа
stop осталось 274688 байт наблюдаемой разницы free; успешная очистка не выполнена.
Метка after_cleanup теперь содержит текущий интервал наблюдения, а не константу
120; это не точное измерение времени выполнения StartModule/StopModule.

## Очередь и безопасность ядра сессии

Клиент имеет одного владельца (RC_NO_THREADS). Транспорт берёт запрос и
публикует ответ через очередь под платформенным lock; callbacks вызываются
владельцем вне lock. Транспорт проверяет cancel/deadline, перестаёт использовать
указатели запроса **до** complete и обязан завершить заимствованный запрос.
Close отменяет queued, но не освобождает ACTIVE за живым транспортом.
Дублирующий/чужой ticket отклоняется; истёкший ответ не принимается как успех.

Допустим только `https://retroachievements.org/dorequest.php`; plain HTTP
и другие URL отклоняются. Это проверка адреса очереди, не реализация TLS.
Два slots, POST <=8 КиБ, response <=64 КиБ, суммарные буферы <=72 КиБ,
deadline 15 секунд. Ответ копируется по размеру, повреждённый JSON обрабатывает
официальный parser. Эти лимиты не доказаны достаточными для всего набора LocoRoco;
PSP fixed heap 32 КиБ может отказать ещё раньше — без расширения до всей free RAM.

Raw request/response и сообщения ошибок библиотеки не логируются. Буферы
запросов/ответов стираются при освобождении. Пароль не сохраняется; токен-файл
или ввод аккаунта в пакете не реализованы. Перед включением аккаунта нужны
выход/удаление токена и отдельные правила его хранения на Memory Stick.
Реальный softcore-зачёт потребует явного разрешения владельца аккаунта.

## Один запуск на PSP

1. Сохрани старые журналы. Скопируй папку `SEPLUGINS/RAClientLite` из
   `PSP_RA_MinimalClient_v0.10.zip` на Memory Stick. Замени оба PRX версии 0.9.
2. Выключи прежние **RAInGameLite и RAInGameProbe**. Включи только новую пробу:

   ```text
   UCUS98662, ms0:/seplugins/RAClientLite/RAClientBootstrap.prx, on
   ```

   RAClientUser отдельно не добавляй. Наличие старых файлов не требует удаления.
3. Полностью перезапусти PSP, запусти тот же LocoRoco USA, пропусти ролик
   и поиграй 2–3 минуты на первом уровне. Wi-Fi не нужен; sleep не проверяем.
4. Выйди HOME, подключи USB. Передай **оба** файла из SEPLUGINS/RAClientLite:
   `client-bootstrap.log` и `client-user.log`, сообщи о работе игры. Отключи пробу.

Ожидается `RC_CLIENT_READY spectator=1 hardcore=0`, растущий idle при frames=0,
успешный client_finished, stop status=0, unload/free и итог bootstrap
result=0 cleanup_result=0 log_error=0. Положительный результат unload допустим.
Отказ memory guard/создания клиента тоже нужно передать; он не считается успехом.
При выключении/зависании отключи пробу, сохрани имеющиеся журналы, не повторяй
сбойный запуск. Повторный запуск перезаписывает только два новых журнала.

## Локальная проверка

`make online-test`: реальный rc_client, синтетические вход/набор/достижение,
отдельный pthread транспорта, доставка на владельце, bounds/cancel/deadline,
дублирующий ticket, pause/frame gate и отсутствие отправки award в spectator.
`make ingame-test`: ранее существующие проверки плюс реальные cleanup-функции
bootstrap с mocks start/stop/unload/free/join/delete, допустимые SMOption,
очистку после NOT_STARTED, удержание ресурсов при неопределённом отказе и повторы.
Проверяется полный путь observer с отказом StartModule на интервале 10:
исходная ошибка сохранена, память восстановлена и после cleanup не записано 120.

PSP-сборка: `scripts/build_minimal_client.ps1`, pinned SDK из dependencies.lock.json,
GCC 15.2.0, Docker/WSL без сети. Наш код собирается с -Werror. У пяти файлов
закреплённого rcheevos отключена format-диагностика %u/%d для uint32_t/int32_t:
PSP newlib использует long, но int/long имеют одинаковый 32-битный ABI, который
проверяется компилятором. Vendor sources не менялись. Сборщик проверяет размер,
rc_client symbols, отсутствие ExitGame/сети/DDR/display/pad в текущем runtime.
В ZIP ровно два PRX, инструкция, install-entry и лицензии rcheevos/PSPSDK.
Сборка и mocks не подтверждают работу на PSP или сетевой зачёт.
