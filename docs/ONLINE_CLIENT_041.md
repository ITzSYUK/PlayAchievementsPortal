# 0.41: меню только после готовности каталога

На PSP0.40 владелец открыл меню во время LOGIN/LOAD. Окно показывало0 OF0,
затем клиент перестал отвечать на сочетание. Установленные PRX совпали со
сборкой. Журналы: Wi-Fi получил IP, SESSION_LOGIN result0, два HTTPS200
(244 и222871 байт, verify0); UI_OPEN до SESSION_LOGIN, затем -35420.
Это ошибка heartbeat меню, а не отказ Wi-Fi/RA. Срабатывание произошло
во время обработки загрузки каталога. Третий startsession остался pending,
игровые проверки не включились (frames0). Очистка в этом запуске завершилась
с cleanup_result0; это не проверка выхода через HOME (module_stop0/home_seen0).

0.40 разрешала modal UI до загрузки каталога. Поток игры ожидал menu heartbeat,
а worker мог больше2с обрабатывать официальный набор. Сработала защита
ui_pause_checkpoint, control.stop отключил меню и клиент.

0.41 сохраняет ранние сетевые карточки, но запрос паузы допускается только
при готовом непустом серверном каталоге. До этого L+R+SELECT показывает
ACHIEVEMENTS LOADING / PLEASE WAIT FOR OFFICIAL SET, пишет UI_WAIT_CATALOG,
не приостанавливает игру и не открывает пустой список. После завершения
load/подготовки101 строк работает обычное меню. Watchdog2с и его остановка
при действительном зависании не изменены. Повторы Wi-Fi/RA и Encore сохранены.

Регрессия моделирует parse3с: прежний ранний запрос воспроизводит -1 watchdog;
пять запросов до готовности не паркуют callback; после готовности три
открытия/закрытия проходят. Отдельно проверяются новые карточки во всех
четырёх framebuffer formats с защитными границами.

make online-test ingame-test — PASS. ASan/UBSan menu lifecycle и UI — PASS.
scripts/build_client_https.ps1 — PASS (закреплённый offline PSPDEV GCC15.2.0).
Конечный PT_LOAD349124 байта при лимите352256, запас3132; exports/heap и
лимит файла проверены.

Последующая проверка на PSP:0.41 загрузила101 достижение, серверный прогресс1,
успешно открыла и закрыла меню повторно (UI_CLOSE restored1). После ошибки
первого APCTL подключения0x80410A08 повтор через1с получил IP; login/set/startsession
завершились HTTPS200, verify0, fault0. Владелец сообщил о трёх последовательных
запусках без перезагрузки и без зависаний. Логи перезаписываются, поэтому
доступна только последняя сессия. Одно более раннее зависание на заставке PSP
после HOME осталось без установленной причины; последующие удачные запуски
его не объясняют. Полнота очистки HOME и длительное восстановление сети
по-прежнему не подтверждены.
Зависимости upstream/rcheevos/PSPDEV прежние (dependencies.lock.json), SDK не
устанавливался. Heap и лимиты памяти/файла от0.40 не увеличиваются.

Заменить только оба PRX, сохранить конфигурацию и auth, полный рестарт PSP.
Во время CONNECTING/LOGIN несколько раз нажать L+R+SELECT: только карточка
загрузки, игра продолжает идти. Дождаться ACHIEVEMENTS LOADED, затем открыть
и закрыть меню несколько раз:101 достижение и серверный прогресс должны быть
видны. Если готовность не наступила, передать оба лога до следующего запуска.
Карта, auth.txt, аккаунт и GitHub агентом не изменялись.
