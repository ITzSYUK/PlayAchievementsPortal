# Онлайн-клиент 0.35: сессия и интерфейс

16 октября 2026. Локальная разработка после подтверждённого зачёта в 0.34.
На настоящей PSP **0.35 пока не проверена**. Результат 0.34 для LocoRoco
не является проверкой новых уведомлений, долгой сессии или расхода памяти.

## Что изменено

- `duration.txt = session` либо отсутствие файла: работа до выхода из игры
  или защитного завершения. Числа 30–300 сохраняют диагностическое окно.
  Режим не меняет разрешение отправлять открытия: это по-прежнему `mode.txt`.
- Убрана остановка HTTPS-загрузчика через 720 секунд. Состояние карты памяти,
  модель игры и минимальный запас свободной памяти продолжают проверяться.
- Журналы ограничены 128 KiB каждый. После заполнения новые записи отбрасываются,
  клиент продолжает работу. Реальные ошибки записи и синхронизации останавливают
  сессию. Конец журнала поэтому не доказывает завершение клиента.
- Уведомление о загрузке набора, текстовые карточки выполнения, подтверждения,
  предупреждения и ошибки. Карточка показывается 4 секунды, загрузка — 2,5 секунды.
  Звук синтезируется при подтверждении сервера; в spectator — при выполнении
  условия. Звук необязательный: отсутствие памяти или свободного аудиоканала
  не мешает отображению и проверке условий.
- Меню со списком, описанием, очками и фильтрами. Метаданные копируются из
  официального набора `rc_client` до включения кадров. Старые `.dat`, `.pach`
  и локальные профили не читаются и не отправляются на сервер.

## Управление и смысл статусов

Удерживать **L + R + SELECT 400 мс**: открыть/закрыть список.
Вверх/вниз — выбор, влево/вправо — страница из 7 строк,
треугольник — следующий фильтр, круг — закрыть. HOME также закрывает меню.

**Меню не приостанавливает игру и не перехватывает кнопки.** Кнопки видит также
сама игра. Для просмотра удобно открыть обычную паузу LocoRoco. Это не остановка
эмуляции: само START-меню не используется как признак запрета `do_frame`.
Принудительное `sceKernelSuspendThread` из старого kernel-интерфейса не перенесено:
оно могло бы остановить владельца клиента/сеть или поток с удерживаемым ресурсом.
При отсутствии игровых callbacks обслуживается `rc_client_idle`, без догоняющих кадров.

| Статус | Значение |
|---|---|
| `LOCKED` | Подтверждённого открытия нет, условие ещё не сработало |
| `PENDING SERVER` | Условие сработало в softcore, подтверждения сервера ещё нет |
| `SERVER CONFIRMED` | Открытие получено с сервера при старте или подтверждено ответом award |
| `CONDITION MET - SPECTATOR` | Локальное выполнение без отправки |
| `SERVER ERROR - UNCONFIRMED` | Серверная ошибка; успешный зачёт не объявлен |
| `UNSUPPORTED` | Официальный движок не может проверять это достижение |

Фильтры `ALL`, `UNCONFIRMED`, `CONFIRMED` относятся именно к серверному зачёту.
Ожидание, ошибка и spectator-выполнение остаются в `UNCONFIRMED`.
Закреплённый `rc_client` в spectator **не загружает открытия аккаунта**.
Меню прямо предупреждает об этом; для такого режима счётчик подтверждений
не является серверным прогрессом аккаунта. В softcore начальные открытия
поступают с официальной сессией сервера.

## Потоки, память и ограничения

Проверка и обработка HTTPS-ответов остаются у сериализованного владельца
`rc_client`. В игровом hook нет отрисовки, звука, файлового I/O или новых ожиданий.
Владелец публикует атомарные состояния строк и ограниченную SPSC-очередь;
worker читает копии и рисует. Сетевой поток не обращается к интерфейсу.
Каталог освобождается только после `engine_stop`; PCM — после завершения звука.

Каталог ограничен 128 достижениями, 96 байтами названия и 256 байтами описания
на строку, включая NUL. Служебные ID от 101000001 не входят в список.
Переполнение каталога останавливает подготовку, частичный список не выдаётся
за полный. Очередь содержит 16 карточек; при переполнении теряются карточки,
но атомарные состояния строк сохраняются. Потери доступны в `UI_STATUS`.
Тексты сокращаются и показываются встроенным латинским шрифтом.
Загрузка значков и живые числовые показатели условий пока не подключены.

Шрифт и подход к непосредственной отрисовке основаны на `plugin/src/overlay.c`.
Старый слой данных/профилей не используется. Поддержаны 480×272, stride 480–512
и четыре формата пикселей PSP. Проверяются адрес, выравнивание и полный размер
буфера в EDRAM либо подтверждённой 40 MiB user partition; kernel-адреса запрещены.
При неверном framebuffer пропускается отрисовка, проверка достижений продолжается.
Качество изображения, мерцание, звук и FPS требуют настоящей PSP.

Измеренный ELF с UI — около 330 KiB, PRX — около 390 KiB.
Лимиты подняты с 320 до 336 KiB для образа и с 384 до 400 KiB для файла.
Preflight учитывает оба новых предела (+32 KiB к требуемой свободной памяти),
прежний free floor 192 KiB и heap 2 MiB сохранены. Настройка ARK не меняется.
Каталог и PCM используют около 56 KiB уже выделенного heap.

Сон/пробуждение и ошибки Wi-Fi пока вызывают защитное завершение, автоматическое
восстановление не реализовано. Нет очереди открытий, переживающей выключение.
Не обещается финальная запись при HOME или мгновенном выключении.
Фреймовый hook остаётся прежним кандидатом, проверенным для конкретной LocoRoco;
полная эквивалентность игровому кадру по-прежнему не объявлена.

## Проверка и следующий запуск

Исходная 0.34 воспроизведена перед изменениями: ELF kernel 19056/user 324916,
`make online-test ingame-test` PASS. Закреплённые исходники: upstream
`e0cd8a9b3ccf439532b24b4f1faf2cfc8c0198ab`, rcheevos 12.5.0
`1433173220a7eaede6a9ed7a18e94117be1821e0`. PSPDEV/PSPSDK из образа
`sha256:511bd8c9eaff77c8a2e205631ae060b9cdf0e9b7e61a7a6ef19482fb4affcdfa`,
GCC 15.2.0; отдельный SHA установленного PSPSDK образ не раскрывает.

В Ubuntu WSL выполнены `make online-test ingame-test` — PASS. Дополнены сценарии
каталога (серверное открытие, spectator, исключение служебного предупреждения),
очереди/фильтров/четырёх форматов пикселей; 50 000 передач между потоками без
нарушения порядка. Переполнение карточек не теряет подтверждённое состояние.
Mock загрузчика проходит прежний предел 720 секунд и завершает работу по
сигналу worker; заполненный журнал не создаёт ошибку.

`test_online_session` и `test_ui` отдельно собраны GCC с
`-O1 -g -std=c99 -Wall -Wextra -Werror -fsanitize=address,undefined`;
запуск с `ASAN_OPTIONS=detect_leaks=1` — PASS. Для первого использованы
`experiments/host/test_online_session.c`, `online/src/ra_client_session.c`,
`build/host/librcheevos.a`, `-D_GNU_SOURCE -DRA_SESSION_ONLINE`, `-lm`;
для второго — `experiments/host/test_ui.c`, `online/src/ra_ui.c`,
`online/src/ra_ui_draw.c`, `-pthread`. Include: `online/include`,
`vendor/rcheevos/include` (для первого также `vendor/rcheevos/src`).

Синтетические изображения меню и карточки проверены визуально на 480×272;
это проверка компоновки, без утверждений о настоящем framebuffer PSP.
`make public-check` и `git diff --check` — PASS.
PSP-сборка: `./scripts/build_client_https.ps1`, Windows PowerShell → Ubuntu WSL →
закреплённый offline Docker (`--network none --pull=never`). Проверяются ELF
0.35, start/stop/info exports, heap, размеры и разрешённые импорты; архив
`build/client-https/PSP_RA_HTTPS_v0.35.zip` содержит только явный список файлов.
Сборка и ELF guards — PASS: kernel 19044 байта, user 337852 байта;
user PRX 399762 байта. ZIP: 20 файлов, каждый сверен с исходным файлом SHA-256,
неожиданных записей и `auth.txt` нет. Байтовые размеры ELF относятся к сумме
text/data/bss, не к длине ELF-файла на диске.

Пакет готовится только локально. Карта, `auth.txt`, аккаунт и GitHub не меняются.
Для первой проверки владелец заменяет оба PRX и `duration.txt` на `session`,
оставляя `mode.txt = spectator`, профиль 2 и ARK +16 MiB. Полный рестарт,
дождаться карточки загрузки, проверить меню/фильтры/описания и закрытие,
поиграть не менее 15 минут (дольше прежних 720 секунд), затем выйти HOME.
Не требуется заново получать уже подтверждённое достижение 397986.
Передать оба журнала и сообщить о мерцании, управлении и замедлении.
Уже пройденный 1-2 не подходит для повторного первого открытия этого условия.

Проверка softcore в аккаунте, сон/пробуждение и отключение Wi-Fi — отдельный
следующий согласованный запуск после проверки интерфейса. Автоматически
карта и аккаунт для этих проверок не используются.
