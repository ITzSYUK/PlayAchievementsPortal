Подготовлено 13 октября 2026 года. Владелец проверил HTTPS Probe **0.2** на PSP-3000, прошивке 6.60 + ARK5: RetroAchievements и положительный контроль `sha256.badssl.com` вернули `0x80431075` на отправке запроса. Wi-Fi получил IP, очистка прошла, журнал записался полностью; дата и время проверены владельцем. Это общий SSL-отказ, его конкретная причина пока неизвестна. Mbed TLS Probe **0.1** дошла до проверки сертификатов на обоих серверах, но отклонила их с `0x0200` (срок ещё не начался): `time(NULL)` в программе вернул секунды 1 января 1970 года. Для чтения UTC через RTC подготовлена Mbed TLS Probe **0.2**. Результат Offline Probe и точный номер сборки CFW пока не получены.

## Установка диагностического пакета

1. Распакуй `PSP_RA_Diagnostics.zip` в корень Memory Stick: появятся папки `PSP/GAME/RAOfflineProbe`, `RAHttpsProbe` и `RAMbedTLSProbe`. В последней нужны **все три файла**: `EBOOT.PBP`, `RAProbeEntropy.prx` и `cacert.crt`.
2. Запускай программы через раздел «Игра» → Memory Stick. Записи в `GAME.TXT` для них не нужны. Существующий плагин и сохранения заменять не требуется.
3. Начни с Offline Probe. Результат на экране должен быть `PASS`; подробности — `stdout.txt` в папке программы. Лог содержит только диагностические результаты.

Offline Probe использует настоящий `rc_client`, но синтетический транспорт и тестовые адреса: она не входит в аккаунт, не читает память запущенной игры и не открывает достижения. `PASS` подтверждает запуск библиотеки и этих автономных проверок на PSP, а не готовность игрового клиента.

## Исправленная Mbed TLS Probe 0.2 — следующий запуск

1. Сохрани логи версии 0.1, затем скопируй всю папку `PSP/GAME/RAMbedTLSProbe` из `PSP_RA_Diagnostics_MbedTLS_v0.2.zip` на Memory Stick с заменой файлов. Запускай **RetroAchievements Mbed TLS Probe 0.2** через «Игра» → Memory Stick. Запись в `GAME.TXT` не нужна.
2. Включи Wi-Fi, выбери рабочий номер профиля вверх/вниз. Начни с **endpoint 1**, `sha256.badssl.com` — он выбран по умолчанию. Крестик запускает один запрос, HOME позволяет выйти во время работы.
3. Дождись результата. Для этого сервера ожидается `SUCCESS`, HTTP 200, `verify_flags=0`, `tls_heap_remaining_bytes=0` и `Log I/O error=0`. При FAILURE сохрани лог независимо от этапа: теперь видны загрузка KIRK-модуля, DNS, TCP, точная Mbed TLS-ошибка и причины отказа сертификата.
4. Выйди крестиком, подключи USB и сохрани **`PSP/GAME/RAMbedTLSProbe/mbedtls-probe.log`** на компьютере как отдельный файл. Каждый запуск его перезаписывает.
5. Перезапусти программу, выбери влево/вправо **endpoint 0**, RetroAchievements, и повтори. Запрос не содержит данных аккаунта. `TLS_OK_HTTP_ERROR` означает успешный TLS при HTTP-ошибке: передай лог, такой ответ не нужно путать с TLS-отказом.
6. После успешного положительного контроля проверь endpoint **2, 3, 4** по одному, каждый раз сохраняя лог. Ожидается **`EXPECTED_CERT_REJECTION`**: просроченный сертификат, несовпадение имени и неизвестный CA соответственно. Общая сетевая ошибка/тайм-аут не считается успешной проверкой сертификата. Endpoint 5 оставлен для проверки DNS.

Нужны логи endpoint 1 и 0; после положительного результата — 2/3/4. Пароль и токен не требуются. Логи не содержат тело HTTP-ответа или случайные seed-байты.

Версия 0.2 передаёт Mbed TLS календарное UTC-время через RTC PSP и пишет `rtc_utc` (дата в UTC), `rtc_utc_epoch` и `tls_utc_epoch`. Значение `libc_utc_epoch` оставлено только для диагностики; для сертификатов оно не используется. Время тайм-аутов берётся из отдельного монотонного счётчика. При ошибке RTC проверка прекращается; срок сертификата продолжает проверяться. Повторно менять правильную дату консоли из-за ошибки 0.1 не требуется.

Проба использует Mbed TLS 3.6.7, TLS 1.2 и отдельный публичный CA-пакет от 25 сентября 2026 года. Проверки цепочки, имени, срока и назначения сертификата обязательны. Штатные `sceHttp`/`sceSsl` не используются. Маленький kernel PRX запрашивает данные генератора KIRK через ARK, останавливается и выгружается; при его отказе проба прекращается. В обоих логах 0.1 этот цикл прошёл успешно на PSP владельца; свойства энтропии этим не доказаны. Программа не устанавливает плагин и не пишет прошивку или настройки.

Лимит памяти Mbed TLS — 2 МиБ, файла CA — 256 КиБ, прочитанной части HTTP — 8 КиБ. Замер `tls_heap_peak_bytes` включает CA и TLS-выделения, но не всю память программы/системных модулей. Проба проверяет заголовки HTTP, полное тело ответа не читает. Не реализованы OCSP/проверка отзыва. Wi-Fi ждёт до 30 секунд, DNS и TCP — по 7; handshake, отправка и чтение заголовков — каждый до 45 секунд между вызовами. Работа внутри игры, сон/пробуждение и расход памяти игрового клиента пока не подтверждены.

## Штатная HTTPS Probe — для сравнения

Версия 0.2 пишет отдельный **`https-probe.log`** в папку программы напрямую через PSP I/O. Старый `stdout.txt` больше не является её диагностическим логом. На стартовом экране и в заголовке нового лога должна быть версия `0.2`.

Перед запуском проверь дату и время консоли, включи Wi-Fi и выбери уже настроенный рабочий сетевой профиль. Программа не создаёт профиль и не записывает параметры роутера.

- Вверх/вниз: номер профиля; влево/вправо: адрес теста; крестик: выполнить один запрос; кружок до запуска: выйти. HOME позволяет выйти во время запроса.
- Индекс 0: публичный endpoint RetroAchievements без параметров и данных входа.
- Индекс 1: контрольный сервер `sha256.badssl.com` с действительным сертификатом.
- Индексы 2, 3, 4: `expired.badssl.com`, `wrong.host.badssl.com`, `self-signed.badssl.com`. Это отрицательные проверки сертификатов.
- Индекс 5: несуществующий домен в зоне `.invalid`, проверка DNS/тайм-аута.

После каждой пробы выйди из программы и сохраняй её `https-probe.log` перед следующим запуском: файл перезаписывается. Запиши номер профиля, индекс endpoint, код ошибки, HTTP-статус и `ssl_peak_bytes`, если он доступен. Тело ответа и сетевые секреты не сохраняются.

Теперь строка `apctl_state` содержит настоящее состояние подключения, например `3 (GETTING_IP)` или `4 (GOT_IP)`, и время ожидания. Метка `begin` записывается перед проверяемым вызовом. Результаты очистки ресурсов также записываются. После завершения на экране показаны этап и код первой ошибки, доступный network errno, HTTP-статус, путь лога и `Log I/O error`. Последний должен быть `0x00000000`; иначе перепиши код ошибки записи и этап с экрана. Эти поля остаются доступны при отказе записи файла. Network errno не является подробным диагнозом сертификата или TLS-handshake.

Положительные запросы должны завершаться `SUCCESS`; отрицательные — отказом. Если ошибочный сертификат принят, лог содержит `UNEXPECTED negative endpoint accepted`: такой транспорт непригоден для входа. Если не проходит ни один положительный запрос, отрицательные ошибки ничего не доказывают о проверке сертификатов: возможны несовместимость TLS, цепочки доверия, DNS или Wi-Fi.

Используются штатные HTTP/SSL-модули и сертификаты PSP. Проверка сертификатов не отключается; её реальное поведение ещё нужно установить на железе. Программа имеет тайм-ауты отдельных операций 7 секунд, ожидания Wi-Fi 30 секунд, лимит заголовков 8 КиБ и тела 32 КиБ. Общий дедлайн чтения 45 секунд проверяется между блокирующими вызовами; это не жёсткое ограничение длительности системного вызова. Она запускается отдельно от игры, поэтому не доказывает доступность стека и отсутствие конфликтов в игровом режиме.

## Первая игра

Выбран кандидат **LocoRoco (USA), оригинальный несжатый ISO**. В [наборе RetroAchievements](https://retroachievements.org/game/10523) есть раннее достижение **Bu Bu Poruche**, условие — пройти уровень Kulche. Это практический выбор для коротких повторных тестов, а не установленный рекорд скорости среди всех PSP-игр.

В [официальной теме игры](https://retroachievements.org/forums/topic/20653) опубликован RA-хеш `199515744d49ef3620a5f9297c6116f9` для USA ISO; старый вариант отмечен как legacy. Это справочное значение, а не хеш образа владельца. Перед интеграцией вычисли хеш своей копии; не переименовывай регион и не подставляй опубликованное значение в клиент.

На компьютере с собранным стендом:

```sh
build/host/hash_probe --iso "/path/to/LocoRoco.iso"
```

Нужен результат реального вычисления. PBP, CSO, переводы и изменённые образы пока не входят в этот эксперимент. Утилита ничего не отправляет в сеть.

Для дополнительного сравнения можно извлечь оригинальные `PSP_GAME/PARAM.SFO` и **зашифрованный** `PSP_GAME/SYSDIR/EBOOT.BIN` из того же ISO и выполнить:

```sh
build/host/hash_probe --files "/path/to/PARAM.SFO" "/path/to/EBOOT.BIN"
```

Если эти два файла положить рядом с `RAOfflineProbe/EBOOT.PBP`, программа попробует вычислить их хеш на PSP. Полученный результат должен совпасть с официальным вычислением для ISO на компьютере. Эта проверка не доказывает, что игровое `disc0:` возвращает те же байты; это отдельный следующий эксперимент.

Пока не нужны пароль, токен или реальный unlock. Следующий шаг после автономных проб — минимальный эксперимент внутри игры для `disc0:`, памяти и кадра, затем проверка условий в spectator.
