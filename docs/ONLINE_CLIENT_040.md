## Повторы подключения

Worker опрашивает собственный APCTL раз в250мс. До первого подключения
принимается только DISCONNECTED: чужая активная сеть не перехватывается.
Профиль задаётся profile.txt, автоматической смены профиля нет. При выключенном
WLAN ожидается включение переключателя. APCTL ERROR больше не останавливает
клиент; ошибки семафора/владения остаются фатальными.

Неудачная попытка/тайм-аут подключения30с запускает задержки1,2,4,8,16,32,60с,
затем60с. Disconnect допускается только после освобождения HTTP mailbox:
worker не уничтожает сокет за спиной transport. Пока нет IP, новые запросы
не выдаются transport; callback игры выполняет условия и rc_client_idle
продолжает обслуживание при паузе, как раньше. Полный сброс сетевого стека
после каждой ошибки не выполняется.

Вход с токеном и загрузка набора повторяются после временных ошибок с теми
же задержками. Токен читается только для попытки входа и сразу стирается из
временной структуры. После обрыва Wi-Fi при загруженной игре сохраняется тот
же rc_client: повторный login/load не сбрасывает условия и ожидающие открытия.
Неверный/просроченный токен, запрет доступа, OOM, ошибки проверки TLS и
некорректные данные не запускают бесконечный повтор. Для них показывается
RA CONNECTION FAILED и нужен разбор кода ошибки/конфигурации.

DNS/TCP, тайм-аут, разрыв ввода/вывода, преждевременный EOF и обрезанное тело
передаются rc_client как retryable. Проверка сертификатов остаётся обязательной.
Полная очередь из двух транспортных слотов — временная занятость; rc_client
сохраняет повтор для достижения. Временные серверные HTTP429/502–504/521–525
обрабатываются официальным движком повторов. У него отдельные интервалы
повтора открытия: первый немедленно, затем1,2,4… до120с. Само подтверждение
по-прежнему требует корректного ответа сервера с нужным AchievementID.
Очередь живёт только в текущем процессе, сохранения после HOME/выключения нет.

## Экран и журнал

UI выделяется до подключения, поэтому карточки работают ещё без каталога.
Список и проверки условий активируются после загрузки серверного набора.
Worker имеет отдельный статус уведомлений, не пишет в SPSC очередь callback.
Карточки: CONNECTING TO WI-FI, CONNECTION FAILED / RETRYING AUTOMATICALLY,
задержка NEXT ATTEMPT IN N SEC, RA LOGIN RETRY, RA SET LOAD RETRY,
WI-FI CONNECTED, RA SERVER REACHABLE и ACHIEVEMENTS LOADED.
WI-FI CONNECTED означает IP, RA SERVER REACHABLE — успешный HTTPS/HTTP200;
ни одна из них не доказывает зачёт достижения. Частые статусы объединяются
в последнее ожидающее уведомление, чтобы не создавать очередь старых карточек.

client-user.log: WIFI_BEGIN, WIFI_SWITCH, WIFI_STATE, WIFI_CONNECT (номер и код),
WIFI_FAILURE (APCTL), WIFI_RETRY_WAIT (задержка), WIFI_RETRY_DISCONNECT,
WIFI_RECONNECTED, RA_ATTEMPT/RA_RETRY (LOGIN/LOAD, результат, HTTP, задержка),
RA_STARTUP_FAILED, HTTP_FAILURE (ticket/code/retry_allowed), RA_SERVER_REACHABLE.
Тела запросов, токены и пароль не журналируются. Существующий лимит лога128KiB
сохраняется: при заполнении клиент работает, новые строки отбрасываются.

## Выход через HOME и сон

Отдельный exit-callback не зарегистрирован; обработчик игры не заменяется.
module_stop уже имеет отмену, join и защитное удержание ресурсов при неясном
времени жизни callback. Однако код не доказывает, что CFW вызывает module_stop
и ждёт его завершения при HOME → выход. Завершение процесса системой не равно
подтверждённой полной очистке самим клиентом. Отсутствие client_finished после
HOME не доказывает сбой.

Добавлены HOME_BUTTON exit=NOT_CONFIRMED (если CFW передаёт кнопку плагину;
это только нажатие, диалог можно отменить) и
STOP_DIAGNOSTIC module_stop/power_flags/home_seen при выполнении
очистки worker. Если ОС прервала процесс раньше, финальных записей не будет.
Меню по-прежнему освобождает паузу/буферы при HOME и проверяет смену display.
Сон/пробуждение в0.40 по-прежнему запрашивает безопасную остановку клиента;
переподключение после сна не заявляется. Это отдельная проверка кадров,
Delta/history и памяти после resume, а не обычный обрыв Wi-Fi.
